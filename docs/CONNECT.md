# 진짜 뮤즈에 연결하기 (실기기 체크리스트)

앱 쪽 코드는 다 만들어졌다. 아래는 **사람만 할 수 있는 일**과 막혔을 때 보는 곳이다.

## 1. SDK 토큰 (뮤즈 계정 필요)
1. https://gadgets.muse.ai 에서 로그인 → Account → **SDK tokens** → 토큰 생성
2. 약관(https://gadgets.muse.ai/sdk-terms)을 읽는다. 개인·비상업 용도, "메타가 만든 것처럼 표시 금지", 공개 광고 금지가 핵심이다.
3. 프로젝트 루트 `local.properties`(깃에 안 올라가는 파일)에 한 줄 추가. **채팅에 붙이지 않는다.**
   ```
   muse.sdk.token=여기에_토큰
   ```

## 2. 폰
- 뮤즈 앱 설치·로그인 → **설정 → 기기 → 개발자 모드 켜기**

## 3. 갤럭시워치8을 맥에 연결 (무선 디버깅)
워치와 맥이 **같은 Wi-Fi**에 있어야 한다.
1. 워치: 설정 → 워치 정보 → 소프트웨어 정보 → **소프트웨어 버전을 7번 탭** → 뒤로 → 개발자 옵션
2. **ADB 디버깅**, **무선 디버깅** 켜기 → "새 기기 페어링" 누르면 IP:포트와 6자리 코드가 뜬다.
3. 맥 터미널에서 (adb 위치: `~/Documents/Default Project/안드로이드-에뮬레이터/android-sdk/platform-tools/adb`):
   ```
   adb pair <페어링 IP:포트>      # 코드를 물어보면 6자리 입력
   adb connect <무선 디버깅 화면의 IP:포트>   # 페어링 포트와 다른 포트다
   adb devices                     # 워치가 device로 보이면 성공
   ```

## 4. 설치
```
tools/install-watch.sh
```
워치 앱 이름은 **뮤즈 참**. 마이크·블루투스 권한은 스크립트가 미리 준다.
(에뮬레이터가 같이 켜져 있으면 `ANDROID_SERIAL=<워치 주소>` 를 앞에 붙여 대상을 고른다.)

## 5. 페어링
1. 워치 앱 화면 아래 **뮤즈 연결** 버튼 → 기기 이름 `MuseGadgetXXXXXX`가 보이고 "뮤즈 앱에서 찾는 중"이 뜬다.
   (이 동안 워치의 블루투스 이름이 잠깐 이 이름으로 바뀌고, 끝나면 원래대로 돌아온다.)
2. 폰 뮤즈 앱: **설정 → 기기 → +(기기 추가)** → `MuseGadgetXXXXXX` 선택 → "커뮤니티 기기" 경고에서 계속
3. Wi-Fi를 물으면 화면에 표시된 네트워크를 고른다(비밀번호 필요 없음).
4. 워치에 "연결됐어요"가 뜨고, 잠시 뒤 "뮤즈에 연결 중…"이 사라지면 온라인이다.
5. 캐릭터를 **꾹 누르고 말한 뒤 떼면** 진짜 뮤즈로 간다. (온라인이 되면 시연 모드 대신 진짜 채널로 자동 전환)

## 막히면
```
adb logcat -s MuseCharm MuseBle
```
출력을 그대로 알려주면 된다. 아직 실기기로 확인하지 못한 가정들:
- 삼성 워치가 BLE 주변기기로 광고하고 블루투스 이름 변경을 허용하는지
- 뮤즈 앱이 워치를 `MuseGadget` 기기로 인식하는지
- 서버가 워치를 기기로 받아주는지(등록 때 종류를 `linux`/`homehub`로 알린다. SDK와 같은 값)
- 음성 노트·응답 구독이 SDK 토큰 기기에서 되는지(메타 펌웨어는 같은 방식)


## 실기기에서 확인된 것 (2026-10-06)
- 갤럭시워치8(SM-L325N, Android 17)은 `MuseGadgetXXXXXX`로 BLE 광고하고, 블루투스 이름 변경도 된다.
- 폰 뮤즈 앱(`com.facebook.aura` 9.0)이 워치를 찾아 연결하고, 암호화 페어링(`pairing_confirmed`)과 Wi-Fi 목록(`wifi_scan_result`)까지 정상 진행된다.
- **막힌 곳:** 폰이 토큰을 보내는 `provision_v2`에서 폰 쪽 `IllegalArgumentException: value should not be longer than max length of an attribute value`
  (`HatchDeviceBleManager.writeChunked`). 안드로이드 14+ 폰은 연결 즉시 MTU를 517로 협상하고(`onConfigureMTU(..., 517)`),
  안드로이드 서버(워치)는 이를 낮출 수 없다. 앱이 그 크기로 512바이트를 넘는 조각을 쓰려다 실패한 것으로 보인다(조각 크기 계산은 로그로 추정).
- **우회:** MTU가 작게 협상되는 기기로 페어링(아이폰/아이패드/안드로이드 13 이하 폰), 또는 맥을 BLE 기기로 써서 페어링.
